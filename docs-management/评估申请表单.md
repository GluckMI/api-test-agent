### 🔥 项目解决的核心痛点

#### 痛点一：传统 API 测试手动重复
**问题：** Postman/Swagger 需要手动操作每个请求，回归测试效率低  
**方案：** YAML 配置一次编写，可重复运行成千上万次

#### 痛点二：断言验证分散
**问题：** 各种验证逻辑散落在不同脚本中，难以维护  
**方案：** 统一断言引擎，内置 10 种标准断言类型（状态码、值相等、类型检查等）

#### 痛点三：步骤间数据传递困难
**问题：** POST 登录获取 Token 后，后续 GET 请求无法自动继承  
**方案：** `extract` 自动提取响应字段 + `${var}` 引用机制，零代码实现跨步骤共享

#### 痛点四：测试结果报告不直观
**问题：** 终端输出混乱，难以整理汇报给团队  
**方案：** 自动生成 HTML（交互式）、Markdown（文本）、JSON（结构化）三种报告

#### 痛点五：CI/CD 集成困难
**问题：** 无法融入 Jenkins/GitHub Actions 自动化流水线  
**方案：** 命令行工具 + 退出码控制（0=成功，1=失败），原生支持 CI/CD

#### 痛点六：学习曲线陡峭
**问题：** Pytest 等框架需要几个月上手，小团队用不起  
**方案：** 声明式 YAML 配置，10 分钟即可写出第一个测试用例

#### 痛点七：多人协作成本高
**问题：** 测试代码修改影响其他成员，版本冲突频繁  
**方案：** YAML 可读性强，Git diff 清晰可见，产品经理也能参与测试设计

### ⚙️ 核心逻辑流

#### 执行流程图
```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│ 加载 test.yaml │ → │ 初始化客户端  │ → │ 循环执行步骤   │ → │ 生成测试报告   │

                             │                    │

                      ┌──────────────┐    ┌──────────────┐
                      │ • base_url   │    │ • 发送 HTTP   │
                      │ • timeout    │    │ • 验证断言    │
                      │ • headers    │    │ • 提取变量    │

```

#### 关键特性分析

| 特性 | 是否包含 | 详细说明 |
|------|---------|---------|
| **长链推理** | ❌ 否 | 线性执行流程，无动态路径选择 |
| **AI 推理决策** | ❌ 否 | 规则驱动，硬编码逻辑 |
| **多 Agent 协作** | ❌ 否 | 单体架构，内部函数调用 |
| **链式数据处理** | ✅ 是 | 步骤 A → extract → 步骤 B（Token 传递） |
| **重试机制** | ✅ 是 | 网络错误自动重试 3 次 |

#### 链式数据处理示例
```yaml
steps:
  # 步骤 1：登录获取 Token
  - name: "登录"
    method: POST
    endpoint: "/login"
    json: { "username": "test", "password": "pass" }
    extract:
      token: "data.token"    # ← 提取响应中的 token
  
  # 步骤 2：使用 Token 调用受保护接口
  - name: "获取资源"
    method: GET
    endpoint: "/resource"
    headers:
      Authorization: "Bearer ${token}"  # ← 引用上一步的 token
```
