## 1. 项目概述

### 1.1 项目背景

API 测试是软件开发流程中的重要环节，但现有解决方案存在明显短板：
- Postman/Apifox等工具需要手动操作，难以自动化
- Pytest+Requests等框架学习成本过高（2 周 +）
- JMeter 配置复杂，性能差
- 缺少适合中小团队的轻量级方案

### 1.2 项目目标

构建一个 **"让 API 测试像写便签一样简单"** 的 Python 框架，实现：
- ✅ 声明式 YAML 配置，10 分钟上手
- ✅ 10 种内置断言类型，满足 80% 场景
- ✅ 智能变量传递机制，零代码跨步骤共享
- ✅ HTML/Markdown/JSON三格式报告自动生成
- ✅ CLI+Python API 双模式，原生支持 CI/CD

### 1.3 核心价值主张

| 受众 | 价值点 |
|------|--------|
| **开发工程师** | 减少样板代码，专注业务逻辑 |
| **测试工程师** | 提升测试覆盖率，降低维护成本 |
| **产品/运营** | 理解接口契约，参与测试设计 |
| **小团队** | 无需专门测试基础设施，开箱即用 |
| **个人开发者** | 免费开源，零成本，自主可控 |

### 1.4 一句话总结

> "一个让 API 测试像写便签一样简单的 Python 框架，通过 YAML 声明式配置和智能变量传递机制，将测试编写效率提升 70%，使非技术人员也能参与 API 测试设计。"

### 4.2 链式数据处理示例

```yaml
name: "完整的登录 + 授权流程"

steps:
  # 步骤 1: 登录获取 Token
  - name: "用户登录"
    method: POST
    endpoint: "https://api.example.com/login"
    
    json:
      username: "${USERNAME}"
      password: "${PASSWORD}"
    
    extract:
      access_token: "data.token"     # ← 提取 Token
      user_id: "data.user.id"        # ← 提取用户 ID
      refresh_token: "data.refresh_token"
    
    assertions:
      - type: status_code
        expected: 200
  
  # 步骤 2: 使用 Token 调用受保护接口
  - name: "获取用户详情"
    method: GET
    endpoint: "https://api.example.com/users/${user_id}"
    
    headers:
      Authorization: "Bearer ${access_token}"
    
    assertions:
      - type: status_code
        expected: 200
      
      - type: equal
        path: "id"
        expected: "${user_id}"
  
  # 步骤 3: 刷新 Token
  - name: "刷新访问令牌"
    method: POST
    endpoint: "https://api.example.com/token/refresh"
    
    json:
      refresh_token: "${refresh_token}"
    
    extract:
      new_access_token: "data.token"
```

### 4.3 是否包含长链推理和多 Agent 协作？

| 特性 | 是否包含 | 详细说明 |
|------|---------|---------|
| **长链推理** | ❌ 否 | 线性执行流程，无动态路径选择，硬编码规则驱动 |
| **AI 推理决策** | ❌ 否 | 基于预设逻辑，不涉及语义理解或智能决策 |
| **多 Agent 协作** | ❌ 否 | 单体架构，内部函数调用，零外部依赖 |
| **链式数据处理** | ✅ 是 | 步骤 A → extract → 步骤 B（Token/ID 传递） |
| **重试机制** | ✅ 是 | 网络错误自动重试 3 次（固定策略） |

**为什么不是真正的"长链推理"？**

| 特征 | 本项目 | 真正长链推理 |
|------|--------|-------------|
| 决策分支 | ❌ 静态流程 | ✅ 动态路径选择 |
| 条件判断 | ❌ 硬编码规则 | ✅ 语义理解 |
| 状态记忆 | ✅ 内存变量 | ✅ 上下文窗口 |
| 自我修正 | ❌ 按预设执行 | ✅ AI 推理调整 |

### 6.3 关键技术决策

| **运行模式** | 本地单机 | 容器化 Docker | K8s 集群 | 弹性扩容需求 |
| **数据存储** | 文件系统 | PostgreSQL | PostgreSQL+Redis | 持久化 + 缓存 |
| **报告存储** | 本地文件 | MinIO/OSS | S3 兼容存储 | 对象存储优势 |
| **API 接口** | CLI+Python | FastAPI REST | REST+gRPC | 多语言 SDK |
| **前端框架** | 无 | React | React+TypeScript | 组件化开发 |
| **身份认证** | 环境变量 | JWT+OAuth2 | Keycloak 集成 | 企业 SSO 需求 |
